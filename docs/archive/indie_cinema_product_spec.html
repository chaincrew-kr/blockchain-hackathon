01

제품 정의

영화 티켓 매출이 발생하는 순간부터 스마트컨트랙트 에스크로에 격리되고, AI가 계약서에서 추출한 정산 규칙에 따라 극장·배급사·제작사·투자자에게 자동 분배되며, 이상 징후 발생 시 해당 금액만 자동 보류하는 B2B 정산 인프라.

관객은 아무것도 바꾸지 않는다. 지금처럼 원화(카드·간편결제)로 표를 산다. 이 제품이 바꾸는 것은 그 뒤에서 벌어지는 사업자 간 정산 구간이다.

┌─ 소비자 레이어 (변경 없음) ──────────────────────────────┐
│  관객 → 원화 결제 (카드/간편결제/예매처, 기존 그대로)        │
│  관객은 본 시스템의 존재를 모른다. 알 필요도 없다.            │
└────────────────────────────────────────────────────────┘
                 │ 발권 데이터만 내려옴
                 ▼
┌─ 정산 레이어 (본 제품) ─────────────────────────────────┐
│  매출/준비금 → 영화별 에스크로 (개인키 없는 PDA, 도산격리)   │
│  AI 에이전트: 계약 해석 · 데이터 검증 · 이상 보류 · 분배 실행 │
└────────────────────────────────────────────────────────┘
설계 제1원칙. AI는 돈을 임의로 나누지 않는다. 분배는 사람이 승인한 결정론적 규칙이 실행하고, AI는 규칙의 생성(계약 해석)과 집행의 검증(이상 탐지)을 담당한다. 승인 후 규칙은 온체인에 고정되어 AI도 바꿀 수 없다.

04

방식 결정 — 팀 합의 사항

A(직접 결제) / B(준비금 예치) / C(PG·신탁 연동) 사이의 혼선을 다음과 같이 정리한다.

구분채택이유
데모 레일방식 A — 시연자가 관객 역할로 테스트 USDC 결제 → 에스크로 직접 유입"자금 격리"라는 핵심 메커니즘을 온체인 실트랜잭션으로 가장 강하게 증명. PG 실연동은 기간 내 불가능
제품 포지션B2B 정산 인프라 — 관객 무접촉관객은 원화로 기존처럼 결제. 모의 구매 페이지는 "관객용 제품"이 아니라 극장 결제 유입을 대신하는 시연 장치임을 발표에서 명시
상용 로드맵세그먼트별: 영화제=A(자체발권) / 상설관=B(준비금+담보감시 P8) / 확장=C(PG·신탁+오라클)C는 개발하지 않고 다이어그램 1장으로만 설명 (오라클 시뮬레이터 — 슬라이드 전용)
발표 자료 필수 문장. "방식 A로 핵심 메커니즘(자금 격리)을 증명하고, 실서비스의 원화 처리(방식 B)는 로드맵으로 제시한다" — 이 선긋기를 명확히 해야 "관객이 왜 크립토로 결제하냐"는 질문이 원천 차단된다.
x402 도입 원칙. Phase 1(지금 개발 대상)은 x402 없이 온체인 이력만으로 완결되도록 설계한다. x402 두 곳(신뢰도 조회·증빙 조회)은 Phase 1 파이프라인이 사람 개입 없이 끝까지 완주된 것을 확인한 뒤, 조건부 분기 훅(hook)에 끼워 넣는 방식으로 Phase 2에 추가한다. 훅의 위치와 조건은 §7 소프트웨어 구성·실행계획서 STAGE 3을 볼 것.

P1·P2·P9는 Phase 2 전용이며 팀 합의 전 초안이다 — 티켓 판매 데이터를 외부에서 가져오지 않는다는 전제(완전 온체인 기본 경로) 위에서 작성했다.
